    Author `test/fixtures/scrub.ts` as a one-shot Node ESM script. Approach: read
    each source FIT byte-stream, walk its messages, re-write PII fields in place
    (preserving on-the-wire field structure), recompute CRC-16/ARC over the
    rewritten body, write the scrubbed bytes to `test/fixtures/fit/<output>.fit`.

    PII fields to overwrite (D-FIT-05 verbatim):
    - **Timestamps:** re-anchor to fixed synthetic epoch `2025-01-01T00:00:00 UTC`. Compute the offset between the source file's first `record.timestamp` and the synthetic epoch; subtract that offset from every `timestamp` field in every message (records, events, sessions, laps, file_id.time_created, etc.). This preserves intra-file timestamp deltas (gap durations, dupe spacing) — only the absolute origin moves. Implementation note: FIT timestamps are uint32 seconds since FIT epoch (1989-12-31 UTC); compute the offset in FIT-second-space, not Unix-ms-space.
    - **GPS lat/lon:** zero out `position_lat` and `position_long` fields in record messages (sint32 zero). The source files are mostly indoor cycling apps so most have these absent already; treat absent as already-scrubbed.
    - **Device serials:** clear `serial_number` in `file_id`, `device_info`, and `file_creator` messages (set to FIT invalid sentinel: 0x00000000 for uint32z, 0xFFFFFFFF for uint32).
    - **User profile:** clear all fields in `user_profile` messages (set to FIT invalid sentinels per type). If the source has no user_profile message, skip silently.
    - DO NOT touch: `power`, `cadence`, `heart_rate`, dev-field declarations, gap structure (timestamp deltas), record count, definition messages, message order, or developer-field bytes (preserves dev-fields-non-shadow.fit's structural shape).

    Implementation choice: rather than a full FIT writer, the scrubber operates as
    an in-place byte rewriter. Use `fit-file-parser` to *parse* the source (to get
    field offsets / definition message lookup), but do the scrubbed-byte emission
    by copying the source buffer and over-writing the specific PII byte ranges.
    After all rewrites, recompute the CRC-16/ARC over the body using the table from
    RESEARCH §Pattern 2 and write the new 2-byte trailer in LE.

    the source to a JS object tree, then write scrubbed bytes via a hand-rolled
