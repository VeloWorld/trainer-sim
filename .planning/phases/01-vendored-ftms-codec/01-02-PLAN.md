    Module shape:
    - Export `interface DecodedIndoorBike { speed?: number; cadence: number; power: number; }`.
    - Export `function decodeIndoorBikeData(view: DataView): DecodedIndoorBike`.
    - At top of file: a JSDoc block explicitly stating: "MIT-licensed (authored in this repo). Spec source: Bluetooth SIG Fitness Machine Service v1.0.1 §4.9 'Indoor Bike Data'. Independent of src/ftms/indoor-bike-data.ts — do not modify by inverting that module's code."
    - Named bit constants citing the spec:
      - `const SPEED_BIT = 0; // FTMS §4.9: bit 0 'More Data' — INVERTED (0 = speed PRESENT, 1 = NOT present). PITFALLS.md #1.`
      - `const CADENCE_BIT = 2; // FTMS §4.9: bit 2 'Instantaneous Cadence Present'. Normal semantics (1 = present).`
      - `const POWER_BIT = 6; // FTMS §4.9: bit 6 'Instantaneous Power Present'. Normal semantics (1 = present).`
    - Read flags via `view.getUint16(0, true)` — the `true` second arg is mandatory (PITFALLS.md #4 — DataView default is BIG-endian; we MUST pass `true` for LE).
    - Compute `speedPresent = (flags & (1 << SPEED_BIT)) === 0` (note `=== 0` — INVERTED per D-04/D-05).
    - Compute `cadencePresent = (flags & (1 << CADENCE_BIT)) !== 0`.
    - Compute `powerPresent = (flags & (1 << POWER_BIT)) !== 0`.
    - Walk the buffer in spec order Flags(2) → Speed(2 if present) → Cadence(2 if present) → Power(2 if present). Field order is per spec and confirmed by RESEARCH.md §Reference Payloads.
    - Speed: `view.getUint16(offset, true) * 0.01` (resolution from PITFALLS.md #3 family — speed is uint16 with 0.01 km/h resolution per spec).
    - Cadence: `view.getUint16(offset, true) * 0.5` (PITFALLS.md #3 — wire = rpm × 2; decode = wire × 0.5).
    - Power: `view.getInt16(offset, true)` (sint16; PITFALLS.md #2 — Auuki's Uint16 is the bug we MUST NOT replicate).
    - Throw `new Error('decodeIndoorBikeData: required fields (cadence, power) missing in flags')` if cadence or power is undefined after parsing.
