Wave 3 (parallel branch B): the real-clock soak suite for REPL-03's drift gate.

Two test files. They run with REAL timers (NOT `vi.useFakeTimers`) because a
soak test measures wall-clock host behavior — fake timers measure algorithm
correctness, which is plan 03-03's domain.

The split (per RESEARCH §Soak test recommendation):

1. **`soak-proxy.test.ts`** — CI tier, ~30 sec runtime. Replays
   `perf-1hr.fit` at compressed speed so the test completes inside CI's
   per-test timeout. This is a **regression detector** for algorithm bugs —
   if a future change reverts to `setInterval` or drops the absolute-target-
   time correction, the proxy catches it. Cannot prove REPL-03 by itself
   because it does not exercise the long-wall-clock environmental envelope.

   (pattern from `test/fit/local.test.ts`). Replays a 30-min slice of
   `perf-1hr.fit` at speed=1 in real time, asserts end-time within 250 ms of
   FIT duration. **This IS the REPL-03 acceptance gate** — the only test
   that exercises the long-wall-clock envelope where OS scheduler hiccups,
   GC pauses, and NTP corrections can show up.

Speed compression math (RESEARCH §Soak test recommendation):
- FIT duration = `records.at(-1).timestamp - records[0].timestamp` ≈ 76 minutes ≈ 4_560_000 ms.
- Target wall-clock = 30_000 ms.
- speed = FIT-duration-ms / target-wall-clock-ms ≈ 152.
- Tolerance: ±2000 ms (proxy headroom; ~7% — 250ms gate scaled by 152x is ~38000ms which would be 2 orders of magnitude looser, so use a tighter ±2000ms practical tolerance).

Slicing math for the real soak:
- Filter records: `records.filter(r => r.timestamp - records[0].timestamp <= 30 * 60 * 1000)`.
- The fixture is 76 min, so the 30-min slice is well-defined.
- After slicing, FIT duration = `slicedRecords.at(-1).timestamp - slicedRecords[0].timestamp` ≈ 30 min.
- Acceptance: `Math.abs(elapsed - fitDurationMs) < 250`.
